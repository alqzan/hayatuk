# خطة منتج «حياتك»

## 1. الرؤية

«حياتك» سوبر آب شخصي عربي، جوّال أولًا، يجمع ما يتشتت اليوم بين تطبيقات الملاحظات والمهام والتقويم والملفات والقراءة والميزانية والورد والذكريات.

الفرق الجوهري ليس كثرة الأقسام، بل أن كل شيء مترابط:

- الهدف يتحول إلى خطة ومهام وجلسات في التقويم.
- الكتاب أو الدورة يرتبطان بهدف، ويُحتسب التقدم من جلسات فعلية.
- الفاتورة ترتبط بميزانية وموعد وتذكير.
- الصورة أو الفيديو أو الصوت يرتبط بذكرى ومكان وتاريخ وملاحظة.
- الورد يرتبط بخطة ختمة ووقت مناسب وسلسلة استمرارية.
- لوحة «اليوم» تعرض ملخص ما أدخله المستخدم بدل أن تعرض عشر لوحات منفصلة.

## 2. مبادئ المنتج

1. **الجوال هو المنتج الأساسي:** التصميم يبدأ من عرض 375–430 بكسل، مع مناطق لمس واضحة واحترام حواف iPhone الآمنة.
2. **التقاط سريع:** زر مركزي واحد لإضافة مهمة أو تذكير أو ملاحظة أو مصروف أو ذكرى أو مادة تعليمية.
3. **العنصر المترابط:** كل عنصر يمكن ربطه بهدف وموعد وتذكير ومرفقات ووسم.
4. **محلي أولًا:** يعمل دون إنترنت، ثم يزامن اختياريًا عند تفعيل المستخدم لذلك.
5. **خصوصية صريحة:** لا وصول للصور أو التقويم أو التنبيهات قبل إذن واضح، ولا مفاتيح أو بيانات شخصية في المستودع.
6. **التقدم من فعل حقيقي:** النسب مشتقة من جلسات وصفحات ودروس ومهام ومعاملات، لا أرقام تجميلية يكتبها التطبيق.
7. **هوية مستقلة:** واجهة عربية هادئة بخلفية زرقاء ضبابية نهارًا وكحلية ليلًا؛ لا تنسخ خلفية «مدار» أو لوحته اللونية.
8. **الإفصاح التدريجي:** الرئيسية تعرض ملخصًا واحدًا وأربعة اختصارات فقط؛ بقية الوحدات تبقى خلف «كل الأقسام».
9. **بداية فارغة:** لا بيانات عرض، ولا اقتراحات مولّدة، ولا محتوى تجريبي؛ لا يظهر إلا ما يضيفه المستخدم بنفسه.

## 3. الهيكل الرئيسي

### شريط التنقل

- **اليوم:** حالة فارغة واضحة أولًا، ثم ملخص مقتصر على بيانات المستخدم واختصارات الإضافة السريعة.
- **خطتي:** الأهداف، الخطط، العادات، المهام، والمراجعة الأسبوعية.
- **إضافة:** صندوق التقاط موحّد.
- **التقويم:** مواعيد وتذكيرات وفواتير وورد وجلسات تعلّم في خط واحد.
- **مكتبتي:** كتب وصوت وفيديو ودورات وأفلام يملك المستخدم ملفاتها أو روابطها.

### وحدات تصل إليها لوحة اليوم والبحث

- الملاحظات والمفكرة.
- المهام والعادات.
- الأهداف والخطط الشخصية.
- الذكريات والصور والفيديو والصوت.
- المكتبة والتطوير الشخصي.
- القرآن والورد والختمة.
- المال والميزانيات والفواتير والأقساط والاشتراكات.
- التقويم والتذكيرات.
- الإحصاءات والمراجعات الأسبوعية والشهرية.

## 4. نموذج البيانات الموحّد

كل كيان أساسي يحمل: `id`, `createdAt`, `updatedAt`, `status`, `tags`, `goalId`, `schedule`, `reminderIds`, `attachmentIds`, و`source` عند الحاجة.

الكيانات الرئيسية:

- `Goal`, `Milestone`, `Task`, `Habit`, `HabitLog`.
- `Reminder`, `CalendarEvent`, `RecurrenceRule`.
- `Note`, `JournalEntry`, `Memory`, `Attachment`, `MediaAsset`.
- `LearningItem`, `LearningSession`, `Bookmark`, `Highlight`.
- `QuranPlan`, `QuranSession`, `DailyWird`.
- `Account`, `Budget`, `Transaction`, `Bill`, `InstallmentPlan`, `Subscription`.
- `DailyPlan`, `WeeklyReview`, `ProgressSnapshot`.

ينبغي ألا يصبح كيان عام واحدًا ضخمًا؛ القاعدة الموحدة للربط، والبيانات المتخصصة تبقى في نماذجها الخاصة.

## 5. ما يؤخذ من «مدار»

يُعاد استخدام الأفكار المعمارية الناجحة، لا بيانات المستخدم ولا الأسرار:

يُؤخذ منه الوضوح والتنظيم فقط، لا الخلفية ولا لوحة الألوان ولا الهوية البصرية.

- واجهة عربية RTL وجوال أولًا مع شريط سفلي واضح.
- تخزين محلي ثم مزامنة اختيارية وحالة مزامنة مفهومة.
- مذكرات على خط زمني ومرفقات صور وصوت وفيديو.
- ورد وختمة وجدولة جلسات القرآن.
- ميزانيات ومعاملات وفواتير وأقساط وتحليلات مالية.
- قراءة وإحصاءات وسلاسل استمرارية.
- استيراد وتصدير ونسخ احتياطي مع اختبارات عدم فقد البيانات.
- فصل منطق المجال عن واجهات المنصة حتى يمكن الانتقال إلى غلاف iOS/Android.

لا يُستخدم مشروع Firebase نفسه، ولا مفاتيحه، ولا أي نسخة من بيانات «مدار» دون تدفق استيراد مستقل وموافقة صريحة.

## 6. المراحل

### المرحلة 0 — النموذج المرئي

- واجهة تفاعلية تعمل على رابط GitHub Pages الحالي.
- تنقل رئيسي، إضافة سريعة، تقدم يومي، أهداف، مهام، مكتبة، تقويم، ورد وميزانية.
- وضع نهاري وليلي، وخط ثمانية العربي المحفوظ داخل المشروع.
- دخول محلي تجريبي بالاسم والبريد الاختياري؛ ليس مصادقة إنتاجية.
- جميع الوحدات تبدأ فارغة، ولا تُضاف أي بيانات عرض أو أفكار تجريبية مسبقًا.
- لا تُرحّل بيانات النموذج السابق إلى الحالة النظيفة الجديدة تلقائيًا.

### المرحلة 1 — الأساس الحقيقي

- تحويل المشروع إلى React + TypeScript + Vite مع PWA.
- قاعدة بيانات محلية ذات مخطط وإصدارات وترحيلات.
- تصميم مكوّنات ونظام ألوان وتباعد موحّد.
- حالات فارغة، بحث شامل، تراجع آمن، وتصدير نسخة احتياطية.
- اختبارات للنسب والتواريخ والترحيلات.

### المرحلة 2 — اليوم والخطة والتقويم

- أهداف ومراحل ومهام وعادات قابلة للإضافة والتعديل والأرشفة.
- تقويم أسبوعي وشهري وجدول يومي.
- تذكيرات متكررة وربط كل تذكير بسبب واضح.
- واجهة تكامل للتقويم والتنبيهات؛ تنفيذ الويب أولًا ثم Capacitor للجهاز.
- مراجعة أسبوعية تبين ما تحقق وما تعثر وتقترح الأسبوع التالي.

### المرحلة 3 — المكتبة والتطوير الشخصي

- استيراد كتب PDF/EPUB وملفات صوت وفيديو ومواد دورات.
- جلسات تعلّم، مؤقت، تقدم، ملاحظات، علامات، وآخر موضع.
- تجميع المواد داخل هدف أو مسار تعلّم.
- دعم أفلام المستخدم المحفوظة كملفات/روابط شخصية فقط، دون توزيع محتوى.

### المرحلة 4 — المفكرة والذكريات

- ملاحظات سريعة ومذكرات غنية.
- صور وفيديو وصوت وملفات مع صور مصغرة وبحث.
- «في مثل هذا اليوم»، خريطة زمنية، وألبومات ذكية.
- حفظ الأصل، كشف التكرار بالهاش، وعدم حذف أي ملف دون تأكيد.

### المرحلة 5 — القرآن والمال

- ورد يومي وخطة ختمة مرنة وجلسات وسلاسل استمرارية.
- نص قرآني من مصدر موثوق مع فحوص سلامة وترخيص واضح.
- ميزانيات دورية، معاملات، فواتير، أقساط، اشتراكات، أهداف ادخار وتنبيهات.
- المال يُخزن بوحدات صغرى صحيحة لتجنب أخطاء الكسور.

### المرحلة 6 — المزامنة والتطبيق الأصلي والذكاء

- حساب اختياري، مزامنة مشفرة، تخزين وسائط، ونسخ احتياطي.
- غلاف Capacitor لـ iOS وAndroid مع تقويم الجهاز والتنبيهات والملفات والمشاركة والقفل الحيوي.
- ملخصات ذكية قابلة للتفسير ومشتقة فقط من بيانات المستخدم واختياراته.
- اختصارات وويدجت وشاشة مشاركة إلى «حياتك».

## 7. التقنية المقترحة

- React + TypeScript + Vite وPWA قابلة للتثبيت من الرابط الحالي.
- Capacitor عند بدء النسخة الأصلية، مع واجهات منفصلة للتقويم والتنبيهات والملفات.
- Zustand للحالة، وقاعدة IndexedDB منظمة مثل Dexie في الويب، مع محول SQLite للنسخة الأصلية عند الحاجة.
- Zod للتحقق من البيانات وترحيلات صريحة للمخطط.
- Firebase منفصل اختياري للمصادقة والمزامنة والتخزين، مع قواعد أمان واختبارات؛ يعمل التطبيق محليًا بدونه.
- Vitest لاختبارات المجال، واختبارات متصفح لمسارات الجوال الحرجة.
- GitHub Actions يبني وينشر إلى المسار `/hayatuk/` على الرابط نفسه.

تُراجع الإصدارات والحزم من مصادرها الرسمية وقت التنفيذ، ولا تُخترع أسماء إضافات Native غير متأكد من صيانتها.
