# برومبت تنفيذي كامل للونا Max / Ultra

أنت فريق منتج وتصميم وهندسة برمجيات خبير. ستطوّر مشروعًا شخصيًا عربيًا اسمه **«حياتك»** ليصبح سوبر آب جوّال حقيقي، جميل جدًا، سريع، خاص، ومفيد يوميًا. لا تكتفِ بإعداد خطة أو شاشات ساكنة: افحص المشروع، نفّذ أول مرحلة كاملة، اختبرها، ثم انشرها.

## السياق والوجهة الإلزامية

- المستودع: `https://github.com/alqzan/hayatuk`
- الفرع المنشور: `main`
- رابط المعاينة الوحيد الذي يجب الحفاظ عليه: `https://alqzan.github.io/hayatuk/`
- **ممنوع إنشاء مستودع جديد أو رابط نشر جديد أو تغيير اسم المشروع.**
- ابدأ بسحب أحدث `main` وافحص كل الملفات الموجودة قبل أي تعديل؛ قد تكون أدوات أخرى قد طورت المشروع بعد كتابة هذا البرومبت.
- حافظ على سجل Git، واجعل التعديلات في commits صغيرة مفهومة، وادفع إلى `main` فقط بعد نجاح الاختبارات والبناء.
- إذا كان GitHub Pages يحتاج إعداد base path فاستخدم `/hayatuk/` وتحقق من فتح المسار الأساسي بعد النشر وإعادة التحميل.

## الرؤية

«حياتك» يجمع في تطبيق واحد مترابط:

1. لوحة اليوم ودرجة اتزان يومية.
2. أهداف وخطط شخصية ومراحل تقدم.
3. مهام وعادات ومراجعة أسبوعية.
4. تقويم وتذكيرات مرتبطة بالأهداف والمهام والفواتير والورد والمواد التعليمية.
5. مفكرة وملاحظات ومذكرات يومية.
6. ذكريات وصور وفيديو وصوت وملفات على خط زمني.
7. مكتبة لكتب PDF/EPUB وصوتيات وفيديو ودورات وأفلام يملك المستخدم ملفاتها أو روابطها، مع تقدم وآخر موضع وجلسات.
8. تطوير شخصي يتابع القراءة والتعلم والوقت والنتائج.
9. ورد قرآني وخطة ختمة مرنة وجلسات وسلسلة استمرارية.
10. مال وميزانيات ومصروفات وفواتير وأقساط واشتراكات وأهداف ادخار وتنبيهات.
11. إحصاءات ومراجعات أسبوعية وشهرية قابلة للفهم.

هذا ليس تجميع أيقونات لتطبيقات منفصلة. العنصر الواحد يجب أن يرتبط بالسياق: هدف ← خطة ← مهمة/جلسة ← موعد وتذكير ← إنجاز يرفع النسبة. فاتورة ← ميزانية ← موعد ← تذكير. كتاب ← هدف تطويري ← جلسات ← تقدم وملاحظات. ذكرى ← تاريخ ← نص وصورة وفيديو وصوت.

## ما نأخذه من «مدار»

افحص مستودع `alqzan/My-dream` للقراءة فقط إذا كان متاحًا، واستفد من أفكاره المعمارية الناجحة: RTL، التخزين المحلي، المزامنة الاختيارية، خط المذكرات والوسائط، القراءة، الورد والختمة، الميزانيات والأقساط، الإحصاءات، النسخ الاحتياطي وفصل منطق المجال عن المنصة.

خذ منه وضوح التنظيم فقط. ممنوع نسخ خلفيته أو لوحته اللونية أو هويته البصرية إلى «حياتك».

ممنوع نسخ بيانات المستخدم أو مفاتيح Firebase أو أسرار المزامنة أو أي ملفات شخصية من «مدار». لا تستخدم مشروعه السحابي نفسه، ولا شعاره أو رموزه الدائرية. أي استيراد مستقبلي يكون تدفقًا مستقلاً، غير هدّام، وبموافقة صريحة.

## القرار التقني للمرحلة الحالية

حوّل المشروع تدريجيًا إلى تطبيق ويب جوّال قابل للتثبيت مع قابلية نقله للتطبيق الأصلي:

- React + TypeScript + Vite باستخدام الإصدارات المستقرة الحالية بعد التحقق من التوثيق الرسمي.
- PWA تعمل دون إنترنت وتُنشر كملفات ثابتة على GitHub Pages.
- Capacitor في مرحلة التطبيق الأصلي لـ iOS وAndroid، مع عدم خلط APIs المنصة داخل صفحات المنتج.
- Zustand للحالة.
- قاعدة محلية منظمة ومفهرسة (مثل Dexie فوق IndexedDB للويب) مع مخطط versioned وترحيلات واختبارات round-trip.
- Zod أو بديل موثوق للتحقق من البيانات عند الاستيراد والترحيل.
- Firebase **منفصل واختياري** لاحقًا للمصادقة والمزامنة والتخزين. التطبيق يجب أن يعمل محليًا دون إعداد Firebase. استخدم `.env.example` فقط ولا تضع مفاتيح أو بيانات شخصية في GitHub.
- Vitest لاختبارات منطق المجال، واختبار متصفح للمسارات الحرجة على مقاسات الجوال.
- لا تخترع اسم إضافة تقويم/تنبيهات أصلية. عند الوصول لـ Capacitor تحقّق من إضافة حالية موثوقة ومصانة، أو اعزل التنفيذ خلف Native bridge.

إذا كان المشروع قد انتقل بالفعل إلى بنية أخرى سليمة، لا تهدمها لمجرد اتباع أسماء الأدوات أعلاه. حافظ على المعمارية الجيدة وحقق نفس المبادئ والنتائج.

## نموذج البيانات

أنشئ نماذج TypeScript منفصلة ومترابطة على الأقل:

- `Goal`, `Milestone`, `Task`, `Habit`, `HabitLog`.
- `Reminder`, `CalendarEvent`, `RecurrenceRule`.
- `Note`, `JournalEntry`, `Memory`, `MediaAsset`, `Attachment`.
- `LearningItem`, `LearningSession`, `Bookmark`, `Highlight`.
- `QuranPlan`, `QuranSession`, `DailyWird`.
- `Account`, `Budget`, `Transaction`, `Bill`, `InstallmentPlan`, `Subscription`, `SavingsGoal`.
- `DailyPlan`, `WeeklyReview`, `ProgressSnapshot`.

الحقول المشتركة: معرف، وقت إنشاء وتعديل، حالة، وسوم، روابط إلى هدف/موعد/تذكير/مرفقات، ومصدر البيانات عند الحاجة. لا تنشئ كيانًا عامًا عملاقًا يحمل كل الحقول الاختيارية.

قواعد مهمة:

- المال يُخزن بوحدات صغرى صحيحة، لا floating point.
- مفاتيح الأيام محلية لتوقيت الرياض، ولا تستخدم UTC بطريقة تغيّر اليوم.
- النسب مشتقة من بيانات فعلية: جلسات وصفحات ودروس ومهام ومعاملات.
- الحذف قابل للتراجع أولًا، ثم تأكيد عند حذف ملف فعلي.
- كل ترحيل مخطط له اختبار يمنع فقد البيانات.
- المرفقات لها hash لكشف التكرار، مع الحفاظ على الأصل وعدم الادعاء أن التشابه البصري تكرار مؤكد.

## تجربة الاستخدام المطلوبة

### الاتجاه البصري الحالي الملزم

- اجعل لـ«حياتك» هوية مستقلة: شعار هندسي خاص غير دائري، ولوحة دافئة مستوحاة من «مدار» (عاجي، ذهبي، أخضر زيتوني، وطيني) نهارًا وبني إسبرسو داكن ليلًا. لا تستخدم شعار «مدار» أو رموزه، بل استخدم ألوانه فقط دون نسخ هويته البصرية.
- استخدم ملفات خط **ثمانية** الموجودة داخل `assets/fonts/` للعناوين والواجهة العربية، وخط Amiri Quran للنص القرآني فقط.
- لا تعُد إلى لوحة طويلة تعرض كل الوحدات دفعة واحدة. استخدم الإفصاح التدريجي: حالة فارغة أو ملخص واحد، أربعة اختصارات، ثم «كل الأقسام».
- أبقِ الوضع النهاري والليلي محفوظين، واحترم تفضيل النظام عند أول تشغيل.
- الدخول الحالي تجريبي ومحلي بلا كلمة مرور. عند إضافة مصادقة حقيقية لاحقًا لا توهم المستخدم أن التخزين المحلي حساب سحابي.
- ابدأ التطبيق فارغًا تمامًا: لا بيانات عرض، ولا اقتراحات جاهزة، ولا أفكار تجريبية. لا يظهر إلا ما يدخله المستخدم.

### لوحة «اليوم»

- تحية وتاريخ محلي.
- عند عدم وجود بيانات، اعرض حالة فارغة هادئة وزر إضافة واضح فقط.
- بعد أن يضيف المستخدم بياناته، اعرض ملخصًا مشتقًا منها وحدها مع شرح موجز لمصدره.
- أربعة اختصارات فقط في أول مستوى: مهمة، تذكير، ملاحظة، ومصروف؛ يبقى زر الإضافة الموحد للأنواع الأخرى.
- الورد والميزانية والذكريات والتطوير تظهر كمساحات مختصرة، والبقية خلف «كل الأقسام».

### «خطتي»

- أهداف نشطة مع نسبة وخطوة تالية.
- مراحل ومهام وعادات مرتبطة بكل هدف.
- مراجعة أسبوعية تسأل: ماذا تحقق؟ ما الذي تعثر؟ ما الخطوة القادمة؟
- لا تعرض نسبًا وهمية؛ النسبة لها معادلة واضحة واختبار.

### «التقويم والتذكيرات»

- عرض يومي وأسبوعي وشهري.
- التذكير يمكن ربطه بهدف أو مهمة أو فاتورة أو ورد أو مادة.
- دعم التكرار والمنطقة الزمنية والتأجيل والإكمال.
- أنشئ `CalendarAdapter` و`NotificationAdapter`: تنفيذ ويب محدود وصريح الآن، وتنفيذ أصلي لاحقًا.
- لا تطلب إذن النظام عند فتح التطبيق. اطلبه فقط عندما يضغط المستخدم «ربط تقويم الجهاز» أو «تفعيل التنبيهات»، واشرح ما سيحدث.
- في نسخة الويب، إذا كان التكامل غير ممكن بالكامل فاعرض ذلك بصدق ولا تدّع نجاح ربط وهمي.

### «مكتبتي»

- استيراد بطاقة/ملف كتاب أو صوت أو فيديو أو دورة أو فيلم شخصي.
- فلاتر، بحث، غلاف، آخر موضع، تقدم، وقت مستهلك، جلسات، ملاحظات وعلامات.
- زر «متابعة» يعيد المستخدم لآخر موضع.
- في الويب يمكن حفظ metadata وملفات صغيرة محليًا ضمن حدود موضحة؛ الملفات الكبيرة تستخدم Storage adapter أو ملف الجهاز في النسخة الأصلية.
- لا توفّر محتوى مقرصنًا أو توزيع أفلام؛ التطبيق يدير ملفات وروابط المستخدم الشخصية.

### «المفكرة والذكريات»

- ملاحظات سريعة ومذكرات غنية.
- صورة وفيديو وصوت وملف في الذكرى نفسها.
- خط زمني، بحث، «في مثل هذا اليوم»، وألبومات.
- لا تحذف أصلًا عند تحسين الصورة أو صناعة thumbnail.

### «القرآن»

- ورد يومي وخطة ختمة قابلة للتعديل، تقدم جلسة، آخر موضع، وسلسلة استمرارية.
- جدولة مرنة وتذكير مرتبط بالتقويم.
- استخدم مصدر نص موثوقًا وترخيصًا واضحًا وفحوص سلامة للنص والترتيب؛ لا تكتب نص القرآن يدويًا من الذاكرة.

### «المال»

- حسابات، معاملات، تصنيفات، ميزانية يومية/شهرية، فواتير، أقساط، اشتراكات وادخار.
- تذكير قبل موعد الفاتورة وربطها بالميزانية.
- لا تنشئ مصروفًا تلقائيًا لمجرد مرور موعد قسط؛ المصروف يسجل عند الدفع أو التأكيد.
- الرسوم توضح المتبقي والمصروف والمتكرر دون ازدحام.

## الاتجاه البصري

- عربي RTL كامل، جوّال أولًا، جميل جدًا وهادئ وفاخر.
- حافظ على الهوية الجديدة: عاجي دافئ نهارًا، بني إسبرسو عميق ليلًا، وذهبي/أخضر زيتوني كلونين رئيسيين مع طيني هادئ كلون مساند.
- لا تجعل الواجهة لوحة إدارة سطح مكتب، ولا شبكة بطاقات متطابقة بلا شخصية.
- استخدم تسلسلًا بصريًا قويًا: بطاقة رئيسية واحدة، ثم الخطوة التالية، ثم التفاصيل.
- خط عربي واضح، أرقام لاتينية داخل المبالغ، مسافات سخية، زوايا ناعمة، وحركات قصيرة ذات معنى.
- مناطق اللمس لا تقل عن 44px حيث يلزم، واحترام `safe-area-inset-*`.
- دعم قارئ الشاشة، لوحة المفاتيح، تقليل الحركة، تباين جيد، وحالات تحميل/فارغة/خطأ.
- نصوص عربية واقعية ومختصرة؛ ممنوع lorem ipsum أو أسماء إنجليزية عشوائية.

## خطة التنفيذ الآن

نفّذ **المرحلة الأولى الوظيفية** في هذه الجلسة، لا تحاول بناء كل النسخة النهائية دفعة واحدة:

1. افحص الحالة الحالية والرابط المنشور وGitHub Pages workflow إن وجد.
2. حافظ مؤقتًا على النموذج الحالي كمرجع بصري، ثم أنشئ بنية React/TypeScript منظمة.
3. ابنِ App Shell وشريط التنقل: اليوم، خطتي، إضافة، التقويم، مكتبتي.
4. أنشئ قاعدة محلية ومخططًا وترحيلًا أوليًا، واجعل الحالة الابتدائية فارغة بلا أي بيانات عرض.
5. اجعل الإضافة/التعديل/الإكمال/الأرشفة تعمل فعليًا للأهداف والمهام والملاحظات والتذكيرات والمصروفات ومواد المكتبة والورد.
6. اربط العناصر: اختيار هدف عند إنشاء مهمة أو تذكير أو مادة، وظهور الأثر في لوحة اليوم والتقدم.
7. اجعل التقويم يعرض التذكيرات والفواتير والورد والمهام المجدولة.
8. اجعل تقدم المكتبة والورد والمهام والهدف مشتقًا ومحفوظًا بعد إعادة التحميل.
9. أضف تصدير JSON واستيراده مع validation ونسخة احتياطية قبل الدمج.
10. أنشئ PWA offline shell، metadata وهوية «حياتك»، مع عدم كسر المسار `/hayatuk/`.
11. أضف اختبارات لمنطق النسب والمال والتواريخ والترحيل والاستيراد.
12. حدّث README بوصف واضح وتشغيل ونشر ومعمارية وخارطة مراحل، دون أسرار.

لا تجعل كل الكود في ملف واحد. افصل على الأقل:

- `domain/` للأنواع والمنطق النقي.
- `data/` للمخزن والترحيلات والاستيراد والتصدير.
- `platform/` للتقويم والتنبيهات والملفات والمزامنة.
- `features/` لكل وحدة.
- `components/` لنظام الواجهة المشترك.

## الاختبارات ومعيار الإنجاز

قبل الدفع:

- شغّل اختبارات الوحدة وفحص الأنواع والبناء الإنتاجي.
- اختبر 375×812 و390×844 و430×932 على الأقل.
- اختبر RTL، التمرير، الشريط السفلي، النوافذ السفلية ولوحة المفاتيح.
- اختبر: إضافة مهمة، ربطها بهدف، إكمالها، ارتفاع التقدم، إنشاء تذكير، ظهوره في التقويم، تسجيل مصروف، تحديث الميزانية، زيادة ورد/مادة، وإعادة تحميل الصفحة وبقاء البيانات.
- اختبر التصدير والاستيراد ورفض ملف غير صالح دون إفساد البيانات.
- اختبر العمل دون إنترنت بعد أول تحميل قدر الإمكان.
- تأكد من عدم وجود أخطاء console أو روابط أصول مكسورة.
- ادفع إلى `main`، انتظر نشر GitHub Pages، ثم افتح `https://alqzan.github.io/hayatuk/`، أعد تحميله، وانتظر استقرار الخدمة، وكرر مسارًا رئيسيًا قبل إعلان الانتهاء.
